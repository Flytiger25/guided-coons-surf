# Git 工作流约定

本项目长期维护的 Git 协作约定，所有提交须遵循本文件。

## 分支模型

- **`main`** — 稳定基线。只接收来自 `dev` 的合并，合入后打版本标签（`v0.1.x`），始终可编译、可运行。
- **`dev`** — 日常开发集散地。所有改动（修 bug、优化、实验）直接提交到 `dev`。

```
main ──── v0.1.0 ──── v0.1.1 ──── ...
          └──────────▲ merge ────┘
dev  ────────────────────────────── 日常开发
```

## 提交规范

遵循 Conventional Commits，**类型用英文、描述用中文**：

```
<type>(<scope>): <中文描述>
```

示例：

- `feat(guide): 新增引导线端点切向约束`
- `fix(coons): 修复节点插入越界问题`
- `perf(solver): 稀疏矩阵装配提速`
- `refactor(coons): 重构投影计算`
- `docs: 更新 README`
- `chore: 补充依赖说明`

常用类型：`feat` / `fix` / `perf` / `refactor` / `docs` / `test` / `chore`

## 提交粒度

- 一次提交只做一件事
- 提交前必须在本地编译通过
- 研究型/实验性代码可以分阶段提交，但提交信息需说明当前所处阶段

## 推送流程

- 任何 `push` 到远程前，须经项目负责人确认
- 常规节奏：本地小步提交 → 阶段完成 → 确认后推送

## 版本标签

- 格式：`v<主>.<次>.<补丁>`，如 `v0.1.0`
- 每次 `dev` 合入 `main` 后打标签

## 验证要求

- 所有合入 `dev` 的提交本地编译通过
- `main` 上的每个标签对应一个可构建的稳定状态
